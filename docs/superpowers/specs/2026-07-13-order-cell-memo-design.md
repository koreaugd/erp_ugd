# 발주관리 탭 — 셀 메모 기능 설계서

- 작성일: 2026-07-13
- 대상: `src/pages/branch/tabs/OrderManagementTabV2.tsx` (지점 화면 > 일일마감정산 > 발주관리 탭)
- 요청: "엑셀 셀 메모처럼, 발주 표의 특정 칸에 특이사항을 기록하고 싶다"

## 1. 배경 / 현재 구조

발주관리 탭은 **행 = 날짜(1일~말일), 열 = 거래처, 칸 = 그날 그 거래처 발주금액**인 피벗 표다.
칸은 `<td>` 안의 `<input>`으로 직접 편집하며, 한 글자 입력할 때마다 즉시 저장된다(자동저장 뱃지 표시).

- 데이터 타입: `OrderItem { id, category, vendorName, amount, memo, orderDate }` (`src/pages/branch/types.ts` L75-82)
- 실질 고유키: `id`가 아니라 **`category | vendorName | orderDate` 3-튜플**. `id`는 입력마다 새로 생성되어 안정적이지 않다.
- 한 (날짜, 거래처) 조합에는 실질적으로 발주 건 1개만 유지된다 (`updateOrderDraft`가 기존 건을 지우고 새 건 1개로 대체).
- 저장: localStorage `erp_orders_{지점명}` + Firestore `shared_data` 문서 (shared key `orders:{지점명}`).
- `memo` 필드는 **타입에 이미 존재하지만 화면에서 전혀 쓰이지 않고**, `updateOrderDraft`가 매 입력마다 `memo: ""`로 덮어쓰고 있다 (L244).

## 2. 확정된 요구사항

| 항목 | 결정 |
|---|---|
| 메모 단위 | **칸(셀) 단위** — (날짜 × 거래처) 조합 하나에 메모 하나 |
| 독자 | **지점 내부용만** — 본사 조회/엑셀 내보내기 연동 없음 |
| 금액 없는 칸 | **메모 불가** — 금액이 입력된 칸에만 메모를 단다 |
| UI | **엑셀식** — 칸 우상단 삼각형 표시 + 호버 말풍선 + 팝업 편집 |

## 3. 사용자 동작 (기능 명세)

### 3.1 메모 있음 표시
- 메모가 있는 칸은 **우상단에 작은 파란 삼각형**이 표시된다.
- 금액 표시(우측 정렬 숫자)를 가리지 않는다.

### 3.2 메모 읽기
- 메모 있는 칸에 **마우스를 올리면** 말풍선(툴팁)으로 메모 전문이 표시된다.
- 터치 기기에서는 **삼각형을 탭**하면 동일한 말풍선이 뜬다 (hover가 없으므로).
- 읽기만 할 때는 팝업을 열 필요가 없다.

### 3.3 메모 쓰기 / 고치기
- 칸을 선택(포커스)하면 그 칸 안에 **작은 메모 아이콘 버튼**이 나타난다.
- 아이콘 클릭 **또는 칸에서 우클릭**하면 메모 입력 팝업이 열린다.
- 팝업 구성:
  - 머리말: `7월 12일 · 비알 · 350,000원` (편집 중인 칸을 명시)
  - `<textarea>` (여러 줄 입력)
  - 버튼: **저장** / **삭제** / (Esc = 취소)
- **저장은 버튼식**이다. 금액 칸처럼 글자마다 저장하면 문장 길이만큼 Firestore 쓰기가 발생하므로, 메모는 저장 버튼을 눌렀을 때 1회만 저장한다.
- 저장 후 팝업이 닫히고 삼각형 표시가 즉시 반영된다.

### 3.4 금액이 없는 칸
- 금액이 비어 있는 칸에서 메모를 열려고 하면 **"금액을 먼저 입력해 주세요"** 안내를 띄우고 팝업을 열지 않는다.
- (금액 없는 칸에는 저장할 `OrderItem`이 존재하지 않기 때문. 요구사항으로 확정됨.)

### 3.5 금액 삭제 시 메모 보호
- 메모가 달린 칸의 금액을 0/빈칸으로 만들면, **"이 칸의 메모도 함께 삭제됩니다. 계속할까요?"** 확인창을 띄운다.
- 취소하면 금액 변경도 되돌린다.

## 4. 내부 설계

### 4.1 데이터 — 스키마 변경 없음
- 메모는 기존 `OrderItem.memo`에 저장한다.
- 저장소·shared key·API 모두 **그대로** (`orders:{지점명}`). 새 테이블/새 키 없음.
- 기존 데이터는 `memo`가 빈 문자열이므로 자동으로 "메모 없는 칸"이 된다. 마이그레이션 불필요.
- 되돌리기(롤백)가 쉽고 기존 데이터가 깨질 여지가 없다.

### 4.2 반드시 고쳐야 할 기존 코드 (핵심)
`updateOrderDraft` (L230-252)는 금액 입력 시 해당 칸의 기존 `OrderItem`을 제거하고 새 객체를 만들면서 `memo: ""`를 박아넣는다.

**→ 기존 칸의 `memo`를 찾아서 물려받도록 수정한다.**
이걸 놓치면 메모를 적어도 금액을 수정하는 순간 사라진다. 이 기능의 성패가 여기 달려 있다.

### 4.3 새로 추가할 것
- `cellMemo(dateKey, vendor): string` — 해당 칸의 `OrderItem`에서 메모를 읽는다. `cellAmount`와 동일한 필터 규칙(현재 `reportCategory` 반영)을 따른다.
- `updateOrderMemo(dateKey, vendor, memo)` — 해당 칸의 `OrderItem`을 찾아 `memo`만 교체하고, 기존 저장 경로(localStorage + `saveSharedDebounced`)로 저장한다. 해당 칸에 발주 건이 없으면 아무것도 하지 않는다.
- 메모 팝업 컴포넌트 — 열려 있는 칸(`{ dateKey, vendor } | null`)만 상태로 관리한다.

### 4.4 기술적 함정 — 팝업이 표에 잘린다
표는 `max-h-[70vh] overflow-auto` 스크롤 박스 안에 있다. 팝업을 `<td>` 내부에 `absolute`로 그리면 **표 경계에서 잘려나간다** (특히 마지막 날짜 행).

**→ 팝업은 칸의 화면 좌표(`getBoundingClientRect`)를 계산해 표 바깥 레이어에 `fixed`로 띄운다.** 칸이 화면 아래쪽이면 위쪽으로 뒤집어 배치한다.

### 4.5 "전체보기"의 합계 칸 — 잠근다 (설계 변경, Codex 리뷰 반영)

당초 설계는 "기존 quirk를 건드리지 않는다"였으나, **틀린 판단이었다.** Codex 적대적 리뷰에서 드러난 내용:

전체보기에서는 같은 (날짜, 거래처)에 대분류가 다른 발주 건이 여러 개 겹칠 수 있고, 칸에 보이는 금액은 그 **합계**다. 이 합계 칸을 낱개 칸처럼 편집하면 어느 쪽이든 틀린다.

- 겹친 건을 모두 지우고 하나로 합침(기존 동작) → **다른 대분류의 발주와 메모가 말없이 유실**된다. 메모 기능이 붙으면서 유실 피해가 커졌다.
- 한 건만 고침 → 사용자가 친 값과 칸에 표시되는 합계가 **어긋난다**.

**결론: 합계 칸(대분류 2개 이상이 겹친 칸)은 편집을 잠근다.**
- 금액 `<input>`을 `disabled` 처리하고 회색 기울임꼴로 표시, 툴팁으로 안내
- 메모 버튼도 감춘다 (메모를 어느 건에 붙일지 정할 수 없으므로)
- 메모 **읽기**(삼각형 표시·말풍선)는 유지 — 정보를 감출 이유는 없다
- 겹친 칸의 말풍선은 겹친 건들의 메모를 **대분류와 함께 전부** 보여준다 (`cellMemoDisplay`). 첫 건의 메모만 읽으면 나머지 건의 메모가 "고칠 수도 없고 보이지도 않는" 상태가 된다 — 잠그는 것과 감추는 것은 다르다
- 수정하려면 위의 대분류 선택에서 하나를 골라야 한다. 대분류당 발주 건은 최대 1개이므로 그 상태에선 칸이 낱개가 되어 모호함이 사라진다

일반적인 칸(발주 건 0~1개)의 동작은 예전과 완전히 동일하다.

### 4.6 메모 조회·저장은 언제나 발주 건 "한 건"만 본다
`cellOrderIndex()`로 칸이 가리키는 건 하나를 못 박고, 읽기(`cellMemo`)와 쓰기(`updateOrderMemo`)가 동일한 그 한 건만 대상으로 한다. 조건에 맞는 건을 모두 갱신하면 다른 대분류의 메모까지 덮어쓴다 (Codex 1차 리뷰 지적).

## 5. 범위 밖 (이번에 손대지 않음)

- 본사/관리자 화면에서의 메모 조회
- 엑셀 내보내기 / 월말마감 워크북 연동 (현재 발주 데이터 자체가 export에 없음)
- 발주 탭의 월말마감 잠금 배선 (현재 없으며, 이번에 추가하지 않음)
- 금액 없는 칸의 단독 메모
- 날짜(행)/거래처(열) 단위 메모
- 다른 탭, 다른 파일

**수정 파일은 `OrderManagementTabV2.tsx` 하나(+ 필요 시 `types.ts` 주석)로 한정한다.**

## 6. 검증 계획

1. `npm run dev` (localhost:3000)로 로컬 실행 후 화면을 사용자에게 보여준다. *(erp_ugd 상시 지침)*
2. 확인 시나리오:
   - [ ] 메모 저장 → 칸 우상단 삼각형 표시
   - [ ] 호버 시 말풍선에 메모 전문 표시
   - [ ] 새로고침 후에도 메모 유지 (Firestore 저장 확인)
   - [ ] **금액을 수정해도 메모가 유지된다** ← 최우선 확인 항목
   - [ ] 메모 있는 칸의 금액 삭제 시 확인창 노출, 취소 시 원복
   - [ ] 금액 없는 칸에서 메모 시도 시 안내 노출
   - [ ] 다른 달로 이동 후 복귀해도 메모 유지
   - [ ] 표 **맨 아래 행**에서 팝업이 잘리지 않음
   - [ ] 대분류 필터 전환(전체 ↔ 식자재 등) 후에도 메모가 올바른 칸에 표시됨
   - [ ] 키보드 이동(화살표/Tab/Enter)이 기존대로 동작하며 메모 UI가 방해하지 않음
3. 배포 전 **Codex 적대적 리뷰** 수행. *(erp_ugd 상시 지침)*
4. 사용자가 "배포해"라고 지시하기 전까지 **커밋·푸시하지 않는다.** *(erp_ugd 상시 지침)*
