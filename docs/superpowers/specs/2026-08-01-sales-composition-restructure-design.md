# 매입매출 탭 — 매출구성 섹션 구조 개편 (2026-08-01)

## 배경

지점 화면 > 월말마감 > 매입매출 탭 상단 "매출집계"의 **매출구성** 카드는 지금 이렇게 되어 있다.

- 메뉴매출 / 주류매출 / 자릿값(예약정산금) / 커버차지(금샤빠 지점만)
- 맨 아래 자동 줄: `실매출과 차이 = 실매출 − (메뉴 + 주류 + 커버차지)`
- 자릿값은 "별도 정산항목"이라며 검산에서 빠져 있는데, 정작 카드 안에 섞여 있어 무엇이 실매출과 대조되는 값인지 화면만 봐서는 알 수 없다.

요청은 카드를 **"POS 실매출과 맞아야 하는 묶음"** 과 **"POS 밖에서 따로 들어오는 예약정산금"** 으로 눈에 보이게 나누고, 각각의 합을 자동으로 보여 달라는 것이다.

## 결정 사항 (사용자 확인 완료)

1. 커버차지 칸은 **전 지점 공통**으로 연다 (기존에는 금샤빠 전용).
2. 마감제출 차단 기준은 **`합계(메뉴+주류+커버차지) = 실매출`** 등식을 유지한다. 예약정산금은 검산에서 제외.
3. 관리자 엑셀은 항목명을 **"자리값" → "예약정산금"** 으로 바꾸고, **"커버차지(자릿값)"** 항목을 새로 추가한다.

## 새 화면 구조 (매출구성 카드)

| 순서 | 라벨 | 종류 | 계산식 |
|---|---|---|---|
| 1 | 메뉴매출 | 입력 (`menuSales`) | — |
| 2 | 주류매출 | 입력 (`liquorSales`) | — |
| 3 | 커버차지(자릿값) | 입력 (`coverCharge`) | — |
| 4 | **합계** | 자동 | 1 + 2 + 3 |
| 5 | 예약정산금 | 입력 (`seatCharge`) | — |
| 6 | **총 합계** | 자동 | 4 + 5 |

- 캐치테이블 안내문(※ 캐치테이블 관리자페이지 → 정산 → 부가세 참고자료)은 **5번 예약정산금 칸 바로 아래**로 옮긴다.
- 기존 "실매출과 차이(메뉴+주류...)" 줄은 **삭제**한다. 같은 정보를 `합계` 줄이 담고, 값이 어긋나면 그 줄이 붉게 뜬다.
- 결제구성·매출요약 카드는 **변경 없음**. 결제구성의 "실매출과 차이"는 이미 `실매출 − (카드결제 + 단순현금 + 현금영수증)` 이라 요청과 일치한다.

### 상태 표시

- `합계` 줄: 실매출이 입력된 상태에서 `합계 ≠ 실매출` 이면 붉은 배경(기존 `autoRow`의 warn 스타일 그대로).
- `총 합계` 줄: 항상 파란 값, 경고 없음. 예약정산금이 더해지므로 실매출보다 크거나 같다.
- 두 자동 줄이 연달아 오므로 구분선은 `합계` 줄 위에만 두고, `총 합계`는 라벨을 진하게(`text-zinc-900`) 해 최종값임을 드러낸다.

## 데이터 모델

`SalesSummary` 인터페이스는 **필드 이름을 그대로 둔다.** 라벨과 배치만 바뀐다.

- `seatCharge` → 라벨 "예약정산금" (값의 의미는 원래부터 캐치테이블 정산금이라 동일)
- `coverCharge` → 라벨 "커버차지(자릿값)", `?` 옵셔널 유지하되 전 지점 필수 입력

필드명을 바꾸면 이미 저장된 마감 데이터를 전부 마이그레이션해야 하므로 건드리지 않는다.

## 검산·차단 규칙 (`computeSalesSummaryWarnings`)

```
합계 = menuSales + liquorSales + coverCharge      // 전 지점 동일, 지점 분기 없음
경고 조건: menuSales·liquorSales·coverCharge·netSales 가 모두 채워졌고 합계 ≠ netSales
경고 문구: "매출구성 합계(X)가 실매출(Y)과 맞지 않습니다."
```

- `salesSummaryUsesCover()`(금샤빠 판정 헬퍼)는 쓰임이 없어져 **제거**한다. 화면·검산 양쪽에서 지점 분기가 사라진다.
- `REQUIRED_FIELDS`에 `coverCharge`를 추가한다 (빈칸이면 마감제출 차단, `0` 입력은 유효).
- `salesSummaryBlankBlocking()`의 금샤빠 전용 `coverBlank` 분기는 `REQUIRED_FIELDS`에 흡수되어 제거된다.
- 검산 규칙은 화면과 마감제출 가드([MonthlySettleTab.tsx:285](../../../src/pages/branch/tabs/MonthlySettleTab.tsx#L285))가 같은 함수를 공유하는 현재 구조를 그대로 유지한다.

## 기존 데이터 영향

커버차지가 전 지점 필수가 되면서 **커버차지가 비어 있던 지점은 `0`을 한 번 입력해야 마감제출이 된다.**

- 검증은 제출 시점에만 도므로 **이미 확정된 과거 월은 영향 없다.** 단 재확정하면 같은 요구가 걸린다.
- **진행 중인 2026-07 마감**은 각 지점이 커버차지에 0을 넣어야 한다. 빈칸은 붉게 뜨고 "해당 없으면 0을 입력하세요" 안내가 이미 있어 막히지는 않지만, 배포 시 지점에 한 줄 공지가 필요하다.
- 배포는 마감 시간대를 피한다(기존 규칙).

## 검증 방법

1. `npm run build` 통과
2. `npm run dev`(localhost:3000)에서 지점 화면 > 매입매출 탭 육안 확인
   - 일반 지점: 4입력 + 합계 + 총 합계 6줄이 뜨는지
   - 금샤빠: 동일하게 뜨고 라벨에 지점별 분기가 없는지
   - 메뉴+주류+커버 ≠ 실매출일 때 합계 줄이 붉게 뜨고 경고 배너가 뜨는지
   - 예약정산금을 넣어도 합계 줄은 안 변하고 총 합계만 커지는지
   - 커버차지를 비우면 마감제출이 막히는지
3. 방향키 이동이 4행 그대로 동작하는지
4. 수정 후 Codex 지독한 리뷰 (상시 지침)
