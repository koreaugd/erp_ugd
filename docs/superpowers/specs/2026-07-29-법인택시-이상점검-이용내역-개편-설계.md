# 법인택시 이상점검·이용내역 개편 설계 (2026-07-29)

설계: Fable 5 / 구현: Opus 5. 로컬(localhost:3000) 확인까지만 — **커밋·푸시·배포 금지**(사용자 지시 대기).

## 배경 (실측 근거)

- 오늘 정윤기 3건(00:48·05:59·19:26)이 전부 낮 시간대 규칙(06~17시) 밖이라 이상점검에 안 잡힘 → 사용자가 시간창을 08~23시로 변경 지시.
- 카카오 `/external/v2/orders` 응답에 **`use_code`**(이용사유, 자유 입력 텍스트)가 이미 실려 옴. 7/27 이후 건부터 입력되기 시작(7월: 계정1 226건 중 8건, 계정2 112건 중 6건). ERP는 현재 이 필드를 슬림화 단계에서 버리고 있음.
- 퀵·택배 = `vertical_code: "logistics"`(상품명 퀵/퀵 급송/라보/다마스), 대리운전 = `"driver"`. 5월 계정1에 logistics 20건 실측. 현재 이 건들은 이용내역·합계·이상점검에 택시와 섞여 있음.

## 1. 이상점검 규칙 변경 — `src/pages/admin/helpers/kakaoTaxiAnomaly.ts`

- `DEFAULT_TAXI_THRESHOLDS`: `dayStartHour: 6 → 8`, `dayEndHour: 17 → 23` (판정은 기존 그대로 `hour >= start && hour < end`, 즉 08:00~22:59 출발 건).
- 파일 머리 주석의 규칙 설계 근거(현재 "낮 시간대 이용을 점검"이라고 6~17시 전제로 서술)를 새 시간창 기준으로 갱신.
- **logistics(퀵·택배) 제외**: `flagTaxiOrders`와 `detectMemberSurges`에서 `row.order.vertical_code === "logistics"` 건은 건너뛴다.
  - 이유: 시간창을 08~23시로 넓히면 업무시간에 부르는 퀵이 전부 '낮 시간대'로 표식돼 소음이 됨. 급증 계산도 퀵 비용이 직원 개인 이용에 합산돼 오탐을 만듦. 퀵·택배는 이용내역 탭의 전용 섹션(§4)에서 사람이 직접 봄.
  - `driver`(대리운전)는 사람 이동이므로 **모든 규칙 유지**.
  - 미매핑 규칙도 logistics는 제외(퀵은 부서 매핑과 무관한 본사성 호출이 대부분).
- 이상점검 화면 상단 안내줄은 threshold 값을 템플릿으로 쓰고 있어 자동으로 "08시~23시"로 바뀜 — 괄호 문구 "(심야 퇴근 택시는 정상 패턴으로 봄)"는 유지.

## 2. 이용사유(use_code) 배선 — 3곳 동기화 + 타입

| 파일 | 변경 |

- GAS는 로컬 확인 후 사용자가 배포를 지시할 때 v41로 배포(이 작업 범위 아님).

## 3. 이상점검 표 개편 — `KakaoTaxiSection.tsx` (점검 대상 건 표)

컬럼 구성(순서): **점검 사유(뱃지) · 이용일시 · 직원 · 지점 · 출발지→도착지 · 이용사유 · 금액**

1. 기존 "사유" 헤더를 **"점검 사유"**로 개명(새 "이용사유" 컬럼과 혼동 방지). 뱃지 마크업은 유지하되 셀·헤더 패딩 `px-4 → px-2`로 폭 축소.
2. **이용일시 축약**: `"YYYY-MM-DD HH:mm:ss"` → `"MM-DD HH:mm"`. 헬퍼 하나 신설(예: `shortTimeText(t)` = 고정 형식이면 `t.slice(5, 16)`, 아니면 원문 그대로) — 이용내역 표와 공용. `title={timeText}`로 전체 시각은 툴팁 제공. "최근 3일" 뱃지·하이라이트 로직(`isRecentOrder`)은 **원본 timeText 기준 그대로**(축약본으로 비교하면 깨짐).
3. **직원 컬럼 폭 축소**: 패딩 `px-4 → px-2` (이름 최대 4자, whitespace-nowrap이라 패딩이 폭의 대부분).
4. **이용사유 컬럼 신설**: 경로 뒤·금액 앞. 자유 입력이라 길 수 있음 → `max-w-[10rem] truncate` + `title`. 값 없으면 빈 칸.
5. 빈 상태 `colSpan` 6→7 갱신.
6. 지점 컬럼도 px-2로 통일(폭 절약). 경로 컬럼은 기존 truncate 유지.

## 4. 이용내역 탭 개편 — `KakaoTaxiSection.tsx`

### 상세 내역 표

컬럼(순서): **이용일시 · 직원 · 지점 · 출발지→도착지 · 이용사유 · 금액 · 구분**

1. 이용일시 `shortTimeText` + `title` 툴팁, 직원·일시 패딩 px-2 — 이상점검 표와 동일 규칙.
2. **계정 컬럼 삭제** (상단 계정 필터 드롭다운은 유지 — 컬럼만 없앰). 
3. 이용사유 컬럼 신설(§3와 동일 스타일).
4. 구분 컬럼 유지 + `VERTICAL_LABEL`에 `logistics: "퀵·택배"`, `driver: "대리"` 추가 (현재 영문 코드가 그대로 노출됨).
5. 빈 상태 colSpan 7 유지(계정 -1, 이용사유 +1).

### 합계 3분할 + 퀵·택배 섹션

1. 합계 그리드 `lg:grid-cols-2 → lg:grid-cols-3`: [지점별 합계] [직원별 합계] [**퀵·택배 내역**(신설)]. 기존 두 표는 자연히 폭이 줄어듦 — 내부 markup 변경 없음.
2. **집계 불변 원칙**: 지점별/직원별 합계·상단 카드(총 금액 등)·카카오 보고 건수 대사(`verifyBranchTotals`)는 **집계 입력을 바꾸지 않는다**(퀵 포함 현행 유지). 새 섹션은 순수 조회용 뷰다.
3. 퀵·택배 섹션 내용: `rows`(계정 필터 적용본)에서 `vertical_code === "logistics"`만, 최신순(timeText 내림차순 — 상세 내역 정렬과 같은 방식). 
   - 헤더: `admin-pill-title` "퀵·택배 내역" + 우측에 "N건 · M원" 요약(11px).
   - 컬럼: 일시(shortTime) · 직원 · 상품(`vertical_product_name` — 퀵/라보 등) · 금액(우정렬). 경로는 행 `title` 툴팁으로만.
   - `max-h-80 overflow-y-auto` — 기존 합계 표와 동일.
   - 빈 상태: "이번 달 퀵·택배 이용이 없습니다." (12px, 기존 empty 톤과 동일)
4. 지점/직원 필터(branchFilter·memberFilter)는 이 섹션에 적용하지 않는다(합계 표들과 동일하게 계정 필터만 따름).

## 5. 검증 스크립트 — `scripts/verify-kakao-multiaccount.mts`

- 기존 픽스처가 6~17시 전제: `10:00`=낮/`21:00`=밤으로 쓰고 있음. **새 규칙에선 21:00도 낮 시간대라 미매핑 전용 픽스처(n5·n6)에 daytime 사유가 추가돼 대표 사유·정렬 기대값이 깨짐** → 미매핑 전용 건은 `23:30` 등 창 밖 시각으로 옮겨 의도(묶음 정렬 검증)를 보존한다. 고액 픽스처(n1·n2)의 시각도 창 밖인지 확인.
- 신규 케이스: ① `vertical_code: "logistics"` 건은 고액·낮 시간대·미매핑 어느 것에도 표식되지 않는다 ② logistics 건은 급증 합산에서도 빠진다 ③ `driver` 건은 여전히 표식된다 ④ 08:00 표식됨 / 07:59 안 됨 / 22:59 표식됨 / 23:00 안 됨 (경계).

## 구현 주의 (이 저장소 함정)

- `AGENTS.md`·`DESIGN_ADMIN.md` 선독 필수. 관리자 화면: 제목은 텍스트만, 헤더/제목 11px·데이터셀 12px(text-xs), `--branch-*` 토큰은 관리자 화면에서 안 먹힘(admin 전용 토큰 `--admin-vanilla` 등 사용 — 기존 뱃지 스타일 답습).

- `use_code`는 옛 캐시/미배포 GAS에서 undefined — `|| ""` 필수.
- 세 곳 동기화 주석(gas/Code.gs ↔ server.ts ↔ gasClient.ts)에 이번 변경도 흔적을 남길 것.
