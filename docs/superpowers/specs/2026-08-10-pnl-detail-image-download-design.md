# 지점 손익계산서 이미지 저장 버튼 — 설계서

작성 2026-08-10 · 승인 완료

## 1. 목적

관리자 화면 `분석 > 지점 손익계산서` 탭의 손익계산서 카드에 **[이미지 저장]** 버튼을 붙인다.
누르면 05 AGENT가 만드는 `output/YYYY-MM/1. 지점별 손익계산서/YYYY-MM_지점명_detail.png` 와
같은 모양의 PNG 가 즉시 내려받아진다. 월말에 05 를 돌리지 않아도 지점 손익계산서 한 장을
카카오톡으로 바로 공유할 수 있게 하는 것이 목적이다.

- 대상 화면: `src/pages/admin/AdminAnalysisSection.tsx` 의 `view === "branch"` 블록
- 원본 형태: `02. 재무 회계/05. AGENT_대시보드 생성/skills/html-renderer/scripts/templates/branch_detail.html`
- 원본 배율: 05 는 body 360px 를 `device_scale_factor=3.0` 으로 캡처한다
  (`skills/png-exporter/scripts/export_png.py:111` — `scale = 3.0 if width <= 400`) → **1080px**

## 2. 산출물

| 항목 | 값 |
|---|---|
| 파일명 | `2026-07_남산광어_손익계산서.png` (지점명 공백은 `_`) |
| 가로 | 1080px (360 CSS px × 3) |
| 세로 | 내용에 따라 가변 (지출 행 수 · 특별지출 유무) |
| 형식 | `image/png`, 브라우저 다운로드 |

## 3. 구현 방식 — 캔버스 직접 그리기

`<canvas>` 2D 컨텍스트에 05 의 CSS 수치를 좌표로 옮겨 직접 그린다.

**이 방식을 고른 이유**
- 앱이 Noto Sans KR 을 자체 호스팅한다(`src/fonts.css`). 05 템플릿도 같은 글꼴이므로
  **글꼴까지 동일한 이미지**가 나온다. 캔버스는 문서에 로드된 웹폰트를 그대로 쓸 수 있다.
- 새 의존성이 0개다. 배포 번들이 커지지 않는다.
- 결정적이다. 화면 상태·스크롤·확대 배율·다크모드에 영향받지 않는다.

**버린 방식**
- *화면 밖 DOM + SVG `foreignObject`* : 05 CSS 를 재활용할 수 있으나 이미지 안에 한글 글꼴을
  통째로 심어야 하고, 실패하면 글자가 대체 글꼴로 깨져 나온다.
- *html2canvas 류 캡처 라이브러리* : 번들 +200KB. 이 앱이 쓰는 Tailwind v4 의 `oklch()` 색
  표기를 못 읽어 색이 틀어지는 문제가 알려져 있다. 게다가 화면 표는 05 형태가 아니라
  어차피 별도 DOM 을 또 만들어야 한다.

## 4. 이미지 구성

05 `branch_detail.html` 과 같은 순서.

```
헤더        UGD · {브랜드}            [ YYYY-MM ]
            {지점명}
─────────────────────────────────────────────
▍손익계산서
            항목      금액     비율   전월대비
            ░░ 매출 ░░
            메뉴 / 주류 / 기타
            ▐ 총매출        100.0%   [뱃지]
            ░░ 지출 ░░
            임대료 … 수수료 (9행 고정)
            [특별지출]  ← 금액 0 이 아닐 때만
            ▐ 총지출                 [뱃지 %p]
            ██ 이익금                    ±%p
───────────── 구분선 ─────────────
PRIME COST 카드 (게이지 + 범례)
───────────── 구분선 ─────────────
▍객단가 & 영수건수 (2칸 카드)
```

### 4.1 헤더
- 윗줄 `UGD · {브랜드}` — **브랜드 = 지점명의 첫 공백 앞부분**.
  `대물섬 종로점 → 대물섬`, `연하동 대학로 → 연하동`, 공백이 없으면 지점명 그대로.
  (05 산출물 16개 지점 헤더 실측으로 확인)
- 아랫줄 지점명, 오른쪽 네이비 알약에 `YYYY-MM`

### 4.2 손익계산서 표

**컬럼 폭** — 05 는 `table-layout:fixed` 에 `colgroup 80/100/44/58`(합 282)을 주고 표 폭을
340px(360 − 좌우 패딩 10px)로 늘린다. 브라우저는 남는 58px 를 지정 폭에 **비례 배분**하므로
실제 폭은 `× 340/282 = 1.2057` → **96.5 / 120.6 / 53.1 / 69.9 px**. 캔버스에는 이 값을 쓰고,
검증 단계(§8-3)에서 실제 PNG 와 겹쳐 어긋나면 실측값으로 바로잡는다.

**매출부** — `메뉴` / `주류` / `기타` → `총매출`
- 화면 표의 라벨(`메뉴매출`·`주류매출`·`배달/기타매출`)이 아니라 **05 표기**를 쓴다.
- 개별 매출 3행의 전월대비 칸은 05 와 같이 **비운다**.
- `총매출` 은 비율 `100.0%` 고정, 전월대비 뱃지 있음.

**지출부** — 9행 고정, **금액이 0이어도 표시**한다
`임대료 · 식재료 · 주류원가 · 인건비 · 공과금 · 기타비용 · 광고비 · 세금예비 · 수수료`
(05 산출물 2026-06/07 전 지점 실측: 금샤빠 광고비 0원도 행이 남아 있다)

**특별지출** — `특별지출 !== 0` 일 때만 10번째 행으로 붙인다.
(2026-07 기준 카라멘야·헴프리스만 해당. 나머지 지점은 0원이라 행 자체가 없다)

라벨은 `특별지출비고` 를 05 규칙으로 해석한다:
- 비고에 `특별지출+=이름(...)` 조각이 있으면 각 조각의 `(` 앞 이름만 뽑아 `+` 로 잇는다
  → `택시비+초기투자상각금액`
- 그런 조각이 없으면 비고 전체의 `, ` 를 `+` 로 바꿔 쓴다 → `렌트비(차량)+인건비(숙소)`
- 비고가 비어 있으면 `특별지출`

**합계·이익금**
- `총지출` — sub-row 양식. 전월대비는 **비율 증감(%p)**
- `이익금` — 네이비 배경 + 앰버 글자. 전월대비는 **이익률 증감(%p)**, 뱃지 없이 글자만

**반올림 규칙 — 05 산출물 61건 전수 대조로 확정 (2026-08-10)**

05 는 비율·증감률을 **소수 첫째 자리로 반올림해 저장한 뒤** 그 값으로 계산·판정한다.
반올림 전 값을 쓰면 아래 네 곳에서 원본과 어긋난다. 실제로 구현 중 전부 겪었다.

| # | 대상 | 규칙 | 어긋난 실례 |
|---|---|---|---|
| 1 | `기타` 비율 | `100 − 반올림(메뉴비율) − 반올림(주류비율)` | 남산광어 2026-06: 직접 계산 0.3% ↔ 05 **0.2%** |
| 2 | `총지출` %p | `반올림(당월 총지출비율) − 반올림(전월)` | 남산광어 2026-06: 직접 5.5%p ↔ 05 **5.4%p** |
| 3 | `이익금` %p | `반올림(당월 이익률) − 반올림(전월)` | 위와 같음(부호만 반대) |
| 4 | 증감률 임계값 | **반올림한 뒤** ±0.5% 와 비교 | 사카바단단 2026-06 임대료: 실제 +0.5315% → 반올림 0.5 → `> 0.5` 아니므로 05 는 **`0.0%`** |
| 5 | PRIME COST | `반올림(식재료율) + 반올림(인건비율)` | 05 저장값 65.1 = 39.1 + 26.0 |

**전월대비 뱃지 색** (임계값은 위 #4 대로 반올림 후 비교)

| 행 | 초록 | 빨강 | 회색 |
|---|---|---|---|
| 총매출 | `> +0.5%` | `< -0.5%` | 그 사이 → `0.0%` |
| 지출 각 행 | `< -0.5%` | `> +0.5%` | 그 사이 → `0.0%` |
| 총지출 (%p) | `< -0.1%p` | `> +0.1%p` | 그 사이 → `0.0%p` |

- 전월 데이터가 없거나 전월 값이 0 이하면 **칸을 비운다**(뱃지를 그리지 않는다).
- **경고행**: 지출 행의 전월대비(반올림값)가 `> +25%` 면 행 배경을 연빨강 `rgba(220,53,69,0.04)` 으로.

### 4.3 PRIME COST 카드
- 값 = `식재료율 + 인건비율`. 식재료율 = 식재료 ÷ **메뉴매출**, 인건비율 = 인건비 ÷ 총매출.
  (ERP `foodRateOf`/`laborRateOf` 와 05 가 같은 산식 — 남산광어 2026-06 실측 39.1+26.0=65.1 일치)
- 게이지: 전체 트랙 폭 대비 `min(원가율,100)%` 를 채우고, 그 안을 식재료:인건비 비로 나눈다.
  식재료 `#2D4A7A`, 인건비 `#E8A838`.
- 목표선: 60% 위치에 빨간 세로선 + `목표 60%` 라벨 (`PRIME_TARGET = 0.60`)
- 범례 3개(식재료율 / 인건비율 / 목표 60%)

### 4.4 객단가 & 영수건수
- 흰 카드 2칸. 값 + 단위(`원`/`건`), 오른쪽 위에 전월비 뱃지(`▲+x%` 초록 / `▼x%` 빨강)
- **05 에 있던 AI 코멘트 2줄은 넣지 않는다.** 그만큼 카드가 짧아진다.
- 값이 0 이면 `—` 로 두고 뱃지는 생략한다.

## 5. 05 PNG 와 달라지는 점 (합의됨)

| | 05 PNG | 이 버튼 |
|---|---|---|
| AI 코멘트 2줄 | 있음 | **없음** — ERP 데이터에 그 문장이 없다 |
| 지출 라벨 치환 | 헴프리스 `임대료→렌트비`, `공과금→인건비(숙소)` | **화면 표와 같은 기본 라벨.** 아래 참고 |
| `-0.0%p` 표기 | 증감이 정확히 0 일 때 `-0.0%p` 로 찍히는 달이 있다 | 항상 `0.0%p` |
| 숫자 출처 | 05 가 db파일을 직접 계산 | ERP 분석 탭이 이미 쓰는 `analysis_pnl_db` |

**지출 라벨 치환을 재현하지 않는 이유** — 05 는 헴프리스의 `임대료` 를 `렌트비` 로, `공과금` 을
`인건비(숙소)` 로 바꿔 찍는다. `특별지출비고`(`렌트비(차량), 인건비(숙소)`)에서 온 것으로 보이지만
두 토큰이 서로 다른 방식으로 쓰이고(하나는 괄호 앞 이름만, 하나는 통째로), `config.yaml` 에도
대응표가 없다. 규칙을 정하는 `render_branch.py` 는 원본이 유실돼 `.pyc` 만 남아 있어 확인이
불가능하다. **추측으로 라벨을 바꾸면 틀린 이름이 든 이미지가 공유된다** — 그래서 화면과 같은
기본 라벨을 쓴다. 영향 받는 지점은 **헴프리스 한 곳**뿐이다(2026-06·07 실측).

**전수 대조 결과 (2026-06·07 지점 30건 × 표 15~16행)** — 위 세 가지를 뺀 **모든 셀이 일치**한다.
숫자·비율·뱃지 문구·뱃지 색·경고행 위치까지 같다.

→ **화면에 보이는 숫자와 이미지 숫자도 항상 일치한다.** 05 PNG 와 숫자가 다르면
업로드된 db 가 다른 것이지 이미지가 틀린 것이 아니다.

## 6. 코드 배치

**새 파일** `src/pages/admin/helpers/pnlDetailImage.ts`
```ts
export interface PnlDetailImageInput {
  branch: string;          // 지점명
  month: string;           // "2026-07"
  current: PnlDbRow;
  previous: PnlDbRow | null;
}
/** 05 branch_detail 형태의 PNG 를 그려 Blob 으로 돌려준다. */
export async function renderPnlDetailPng(input: PnlDetailImageInput): Promise<Blob>
```
- 화면 컴포넌트를 모른다. 입력은 데이터, 출력은 Blob 뿐이다.
- 파일 안에 05 의 색·치수를 상수로 모아 둔다(`TOKENS`, `METRICS`).
- 그리기 전에 `await document.fonts.ready` 로 글꼴 로딩을 기다린다.
  기다리지 않으면 첫 클릭에서 글꼴이 대체 글꼴로 깨져 나온다.

**수정** `src/pages/admin/AdminAnalysisSection.tsx`
- 손익계산서 카드 제목줄 오른쪽에 버튼 하나. 클릭 → `renderPnlDetailPng` → `URL.createObjectURL`
  → 임시 `<a download>` 클릭 → `revokeObjectURL`
- 진행 중에는 버튼을 비활성화하고 `저장 중…` 으로 바꾼다(중복 클릭 방지).
- 실패하면 버튼 옆에 짧은 오류 문구를 띄운다(무음 실패 금지).

## 7. 디자인 규칙 준수

- 버튼 색·모양은 `DESIGN.md` 의 관리자 토큰을 쓴다. `--branch-*` 토큰은 관리자 화면에서
  안 먹으므로 쓰지 않는다(메모리 `erp_salary_change_history_tab` 함정).
- 밴드 제목은 텍스트만 — 버튼은 밴드 안이 아니라 밴드 오른쪽 끝 또는 카드 본문 상단 우측에
  둔다. `AGENTS.md:59` 의 "섹션 제목은 텍스트만(아이콘·이미지 금지)" 규칙과 충돌하지 않게.

## 8. 검증

1. `npm run lint` (tsc --noEmit) 통과
2. `npm run dev` 로 로컬에서 열어 **화면을 사용자에게 보여준다** (배포 전 로컬 확인 상시지침)
3. 2026-06 남산광어로 저장한 PNG 를
   `output/2026-06/1. 지점별 손익계산서/2026-06_남산광어_detail.png` 와 나란히 놓고 대조한다.
   - 숫자 12행이 모두 같은지
   - 뱃지 색·부호가 같은지
   - 컬럼 폭·행 높이가 눈에 띄게 어긋나지 않는지
4. 특별지출이 있는 지점(카라멘야 2026-07)으로 10행 케이스를 확인한다
5. 전월 데이터가 없는 달(첫 달)에서 전월대비 칸이 비는지 확인한다
6. 수정 직후 Codex 지독한 리뷰 (상시지침 `erp_codex_review_standing_rule`)

## 9. 하지 않는 것

- 본사 종합 탭에는 버튼을 넣지 않는다(이번 요청 범위 밖).
- 05 AGENT 쪽 코드는 건드리지 않는다.
- 여러 지점 일괄 저장·ZIP 은 하지 않는다.
