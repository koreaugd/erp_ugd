# 매입매출 탭 "작성방법 보기" 안내 말풍선 — 설계

- 작성일: 2026-07-10
- 대상 화면: 지점화면 > 월말마감정산 > **매입매출** 탭
- 목적: 처음 쓰는 점장이 섹션별 작성 규칙(특히 체크박스에 따라 열리고 잠기는 금액칸)을 화면 위에서 바로 확인하며 작성하게 한다.

## 1. 결정 사항

| 항목 | 결정 | 이유 |
|---|---|---|
| 표시 방식 | **토글식 동시 표시** — 버튼을 누르면 안내 말풍선이 모두 켜지고, 다시 누르면 사라진다 | 안내를 켜둔 채로 작성할 수 있어야 한다 |
| 배경 | **어둡게 하지 않는다.** 말풍선 바깥 클릭은 화면으로 통과한다 | 안내 중에도 입력·저장이 가능해야 한다 |
| 말풍선 위치 | **떠 있음**(레이아웃을 밀지 않음). 말풍선마다 `placement`로 위/아래/안쪽오른쪽위 지정 | 사용자 선택. 가릴 수 있으므로 말풍선마다 개별 닫기(X)를 둔다 |
| 문구 관리 | **코드에 고정** (한 파일에 모음) | 어드민 편집 UI는 작업량 2~3배. 문구 수정은 배포로 처리 |
| 자동 노출 | **수동만** (버튼을 눌러야 켜짐) | 매달 쓰는 익숙한 점장을 방해하지 않음 |
| 재사용 | **공용 부품 + 탭별 문구 목록** | 다음 탭은 문구 목록만 추가하면 됨 |
| 구현 | **자체 컴포넌트** (라이브러리 없음) | React 19 지원 문제 회피, 기존 CSS(`!important` 다수)와 충돌 회피, DESIGN.md 토큰 그대로 사용 |

### 설계 변경 이력
초안은 배경을 어둡게 하고 `이전/다음`으로 넘기는 **단계별 투어**였다. 사용자 검토 결과 "안내를 띄워둔 채로 작성"이 핵심 요구로 드러나 **토글식 동시 표시**로 바꿨다. 이에 따라 단계 이동·진행표시(`1/4`)·배경 어둠 처리를 모두 제거했고, 합계 배너 안내는 불필요하다는 판단으로 뺐다.

검토했으나 채택하지 않은 대안: 외부 라이브러리(driver.js, react-joyride) — 의존성 증가와 스타일 충돌. 섹션 위에 끼워넣어 레이아웃을 미는 방식 — 입력칸을 가리지 않는 장점이 있으나 사용자가 떠 있는 쪽을 선택.

**기존 3개 파일은 `data-guide` 속성 추가와 버튼 1개 렌더만 한다.** 저장·자동저장(디바운스/pending 플래그)·마감 확정 게이트·선입금 미러링 로직은 한 줄도 건드리지 않는다. 속성 추가는 런타임 동작에 영향이 없으므로 이 탭의 예민한 부분에 회귀 위험이 없다.

### 인터페이스

```tsx
// guideSteps.tsx — 문구에 표(JSX)가 들어가므로 .tsx
export interface GuideStep {
  anchor: string;  // data-guide 속성값. 화면에 없으면 그 말풍선을 그리지 않는다
  id?: string;     // 한 앵커에 말풍선을 둘 이상 붙일 때 구분자. 생략하면 anchor를 쓴다
  title: string;
  body: ReactNode;
  width?: number;  // 기본 340px
  placement?: "below" | "above" | "inside-top-right";  // 기본 inside-top-right
}

// GuideCallouts.tsx
export function GuideCallouts(props: {
  open: boolean;
  steps: GuideStep[];
  onClose: () => void;  // Esc로 전체 닫기
}): JSX.Element | null;
```

`GuideCallouts`는 `steps`만 받는다. 어떤 탭인지, 어떤 데이터인지 모른다. 다른 탭에 붙일 때 이 파일은 수정하지 않는다.

## 3. 안내 말풍선 4개

앵커 이름은 `data-guide` 속성값이다. 말풍선은 **섹션 전체가 아니라 그 규칙이 실제로 적용되는 칸**에 붙인다.
거래처 표처럼 **한 앵커에 말풍선을 둘 붙일 때는 `id`로 구분**하고, 하나는 `inside-top-right`, 다른 하나는 `above`로 놓아 서로 겹치지 않게 한다.

### `sales-summary-seat-charge` · 자릿값(예약정산금) — 매출집계의 자릿값 입력칸, 아래에 배치, 너비 400px, 글머리 기호 목록
- 자릿값(예약정산금)은 매출 합계에 들어가지 않습니다. 별도 정산 항목이라 검산에서 빠집니다.
- 캐치테이블 이용 매장은 **캐치테이블 관리자페이지 → 정산 → 부가세 참고자료 → 해당 월 선택**(붉은 굵은 글씨) 후 나오는 금액을 입력하세요.

### `sales-summary-month` · 결산월 선택과 마감 — 매출집계 카드의 결산월 달력칸, 아래에 배치, 너비 560px

- 마감 버튼은 두 개다. 위쪽 매출집계와 아래쪽 매입매출은 서로 독립적이다. — 넓은 화면에서 한 줄에 들어가야 하므로 `sm:whitespace-nowrap`. 폭 560px은 이 줄에 맞춘 값이다. 좁은 화면에서는 줄바꿈을 허용한다(안 그러면 글자가 말풍선 밖으로 잘린다).
- 확정하면 입력칸이 잠긴다. 고치려면 `수정` 버튼으로 잠금을 푼다.

### `purchase-table` / id `purchase-table-guide` · 거래처 표 작성방법 — 표 위(above), 너비 860px
체크박스 규칙과 비알(BR) 작성법을 **한 말풍선에 좌우 2열**로 담고 가운데 **세로 회색선**으로 나눈다. 좁은 화면(`sm` 미만)에서는 위아래로 쌓이고 구분선이 가로선으로 바뀐다. 표·버튼을 잠깐 가려도 되도록 위쪽에 둔다(사용자 요청) — 몸통은 클릭이 통과하므로 가려진 버튼은 그대로 눌린다.

**왼쪽 — 체크박스와 금액칸.** 체크 상태는 `☐`/`☑` 문자가 아니라 **lucide `Square`/`SquareCheck` SVG 아이콘**으로 그린다 — 한글 글꼴에 U+2610/U+2611 글리프가 없어 물음표나 빈 네모로 깨지기 때문. `sm` 미만에서는 5컬럼 표 대신 카드(같은 `CHECKBOX_RULES`).

## 4. 동작 세부

**버튼** — 페이지 맨 위, 매출집계 카드 바로 위에 오른쪽 정렬. DESIGN.md에서 "공지·안내"에 배정된 `--branch-vanilla`(#EFF0A3) 배경 + `--branch-black` 테두리. 켜진 상태에서는 색을 반전(검정 배경 + 바닐라 글자)하고 문구를 `작성방법 닫기`로 바꿔 토글임을 드러낸다. `aria-pressed`로 상태를 알린다.

**마감 잠금과 로딩** — 마감이 확정돼 화면이 잠긴 상태에서도 버튼은 활성이다(잠긴 뒤에 규칙을 찾아보는 경우가 많다). 반면 **로딩 중에는 버튼을 잠근다** — 거래처 표가 아직 그려지지 않아 그 말풍선이 통째로 빠진 채 열리기 때문이다.

**클릭 통과** — 감싸는 층도, **말풍선 몸통도** `pointer-events: none`이다. 클릭을 받는 것은 **닫기(X) 버튼 하나뿐**이다. 말풍선이 입력칸이나 버튼을 덮더라도 그 아래를 그대로 쓸 수 있다.

말풍선 몸통까지 클릭을 받게 두면, 좁은 화면에서 말풍선 폭이 화면에 맞춰 늘어날 때 아래 버튼(예: `매입 업체 추가`)을 가로막는다. 특히 `above` 배치는 앵커 위 영역을 덮으므로 이 문제가 확실히 난다. 몸통을 통과시키면 배치와 무관하게 안전하다. 대가로 말풍선 안의 글자를 드래그 선택할 수 없다 — 읽기 전용 안내이므로 감수한다.

**겹침 순서** — 말풍선은 `z-30`. 사이드바(`z-40`)와 토스트 알림(`z-50`)보다 **아래**에 둬서 그 둘을 가리지 않는다.

**개별 닫기** — 말풍선이 입력칸을 가릴 수 있으므로 각 말풍선에 X 버튼을 둬 하나씩 치울 수 있다. 버튼으로 다시 켜면 초기화된다. `Esc`는 전체를 닫는다.

**생김새** — 말풍선임을 알 수 있게 **붉은 테두리**(`border-2 border-rose-600`)를 두른다. 앵커에도 옅은 붉은 테두리를 둘러 어느 칸의 안내인지 잇는다. 제목줄은 DESIGN.md의 "공지·안내" 색 `--branch-vanilla`(#EFF0A3).

**배치 규칙** — 말풍선마다 `placement`를 지정한다.
- `below` — 앵커 바로 아래에 붙이고 위쪽을 가리키는 꼬리를 그린다. 입력칸처럼 **작은 앵커용**이다. 위에 덮으면 그 칸을 가려 작성할 수 없기 때문.
- `above` — 앵커 바로 위에 붙이고 아래쪽 꼬리를 그린다. 말풍선 높이를 그리기 전에는 알 수 없으므로, 앵커 위쪽 모서리에 놓고 CSS `translateY(-100%)`로 끌어올려 **높이 측정을 피한다.**
- `inside-top-right`(기본) — 앵커 안쪽 오른쪽 위에 겹친다. 거래처 표처럼 **넓은 앵커용**.

너비는 `width`로 말풍선마다 정한다(기본 340px). 내용 길이에 맞춰 조정한다.

**위치 계산** — 화면(viewport) 좌표가 아니라 **문서(document) 좌표**로 잡고 `document.body`에 포털로 붙인다. 화면 좌표로 고정하면 접힌 아래에 있는 앵커(거래처 표)의 말풍선이 잘리거나 서로 겹쳐, "3개가 동시에 켜진다"는 요구가 깨진다. 문서 좌표에 붙이면 말풍선이 앵커를 따라 자연스럽게 스크롤되므로 **스크롤 리스너가 필요 없다.** 본문은 `window`가 스크롤한다(내부 `overflow-y` 컨테이너 없음)는 전제에 의존한다.

문서 좌우를 벗어나지 않게 가둔다. 늦게 그려지는 섹션과 높이 변화는 `ResizeObserver`(body)와 `resize`로 따라간다. **화면 밖이라는 이유로 말풍선을 생략하지 않는다** — DOM에 앵커가 없을 때만 건너뛴다. `ResizeObserver` ↔ 리렌더 순환을 막기 위해 계산 결과가 이전과 같으면 상태를 갱신하지 않는다.

**모바일/태블릿** — 화면이 좁으면 말풍선 너비를 화면에 맞춰 줄인다(`min(width, 100vw - 24px)`).

말풍선 안의 표에는 **가로 스크롤을 두지 않는다.** 몸통이 클릭을 통과시키므로 손으로 밀 수가 없어, 스크롤이 필요해지는 순간 그 내용은 영영 볼 수 없게 된다.

체크박스 규칙표는 5컬럼이라 휴대폰 폭(≈320px → 말풍선 내부 ≈264px)에서 컬럼당 40px도 안 남아 뭉개진다. 그래서 **`sm` 미만에서는 표 대신 카드 형태**로 그린다. 두 형태 모두 `CHECKBOX_RULES` 배열 하나에서 그려 내용이 어긋나지 않게 한다. 비알 표는 2컬럼이라 그대로 둔다.

## 5. 범위 밖 (YAGNI)

- 어드민에서 문구 편집하는 UI
- 첫 방문 자동 실행, "다시 보지 않기" 저장
- 말풍선 드래그로 옮기기 (개별 닫기로 충분)
- 합계 배너 3장 안내 (사용자 판단으로 제외)
- 매입매출 외 다른 탭의 문구 (구조만 준비하고 이번엔 추가하지 않음)

## 6. 검증

저장 로직을 건드리지 않으므로 데이터가 깨질 위험이 없다. 확인은 화면으로 한다.

1. `npm run lint`, `npm run build` 통과
2. Codex 지독한 리뷰 (AGENTS.md 상시 지침)
3. `npm run dev` → `http://localhost:3000` 에서 사용자가 직접 확인
   - 버튼을 누르면 말풍선 4개가 한꺼번에 뜨고, 다시 누르면 사라지는가
   - 말풍선을 켜둔 채로 입력칸에 값을 넣을 수 있는가 (클릭이 통과하는가)
   - 각 말풍선이 맞는 칸에 붙는가 (앵커 테두리가 붉게 표시됨)
   - 거래처 표의 두 말풍선(표 위 / 표 안쪽 오른쪽 위)이 서로 겹치지 않는가
   - 스크롤해도 말풍선이 앵커를 따라오는가
   - 개별 X로 하나만 닫히는가, `Esc`로 전부 닫히는가
   - 마감 확정된 달에서도 버튼이 눌리는가 / 로딩 중에는 잠기는가
   - 다른 탭(정직원 급여대장 등)에는 버튼이 보이지 않는가
   - 창을 좁혔을 때 말풍선이 화면 밖으로 나가지 않는가
